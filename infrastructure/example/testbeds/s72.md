# S72 Testbed Setup

This guide explains how to deploy an OCUDU split 7.2 testbed with an Amarisoft UE Simulator (UESIM). It complements the [IaC full example](../README.md) with the network, timing, host and Retina configuration required to replicate the testbed.

## Required resources

- 1 gNB node to run OCUDU, with two fronthaul NIC ports available to DPDK.
- 1 UESIM node to run Amarisoft UE and the core workload, with two fronthaul NIC ports and a separate backhaul interface.
- 1 PTP-capable fronthaul switch with a valid GPS input, acting as the PTP grandmaster.
- Amarisoft UE and MME licences available to Retina.

The gNB and UESIM hosts need sufficient CPU, memory, disk and hugepages for the selected test profile. The UESIM node must be reserved for the realtime workload while a test is running.

## Network design

Use two fronthaul links, one VLAN per link. The switch ports connected to the gNB and UESIM NICs must carry the assigned VLANs as tagged traffic. The two hosts must use the same ordering for links, MAC addresses and VLAN IDs.

| Link | gNB side | UESIM side | Switch requirement |
| --- | --- | --- | --- |
| Fronthaul 1 | DPDK-bound physical NIC | Linux VLAN interface `<uesim-fh-iface-1>.<fh-vlan-1>` | Carry `<fh-vlan-1>` between both ports |
| Fronthaul 2 | DPDK-bound physical NIC | Linux VLAN interface `<uesim-fh-iface-2>.<fh-vlan-2>` | Carry `<fh-vlan-2>` between both ports |
| Backhaul | gNB backhaul interface | UESIM backhaul interface | Reachable from the core network; not part of S72 |

Set the fronthaul MTU to 9600 on the UESIM physical NICs. Create the VLAN interfaces persistently from the node's TuneD startup script, for example:

```bash
ip link set dev <uesim-fh-iface-1> mtu 9600
ip link add link <uesim-fh-iface-1> \
  name <uesim-fh-iface-1>.<fh-vlan-1> type vlan id <fh-vlan-1>
ip link set dev <uesim-fh-iface-1>.<fh-vlan-1> up
```

Apply the equivalent configuration to the second interface. Do not create these interfaces manually as a permanent configuration: they must be recreated after each boot by the managed node configuration.

## PTP synchronisation

S72 requires accurate timing. The fronthaul switch is the PTP grandmaster; it must have GPS lock before tests are run. Configure `linuxptp` on the UESIM node as a client on a fronthaul interface. The standard profile uses hardware timestamping, Layer-2 transport and E2E delay measurement; use the PTP domain configured for the target cluster.

Do not run NTP, chrony or systemd-timesyncd as a competing time source on a PTP node. In the cluster, `linuxptp` is deployed from `cluster_definition/<cluster>/services.yaml`.

## Host tuning

The UESIM node needs the realtime TuneD profile and NIC tuning supplied through `services.yaml`. At minimum:

- reserve housekeeping CPUs and isolate the realtime CPUs used by the UE workload;
- configure kubelet's fractional `systemReserved.cpu` according to the approved profile instead of `reservedSystemCPUs`; when changing this setting, reset kubelet's CPU manager state so the allocation is recalculated;
- use the `performance` CPU governor and configure the required hugepages;
- disable adaptive interrupt coalescing on the fronthaul NICs;
- configure the approved RX/TX ring sizes for the NICs;
- tune the backhaul interface separately from the fronthaul interfaces.

The gNB node must expose the two fronthaul PCI addresses to the gNB DPDK configuration and provide the CPU isolation, DPDK EAL arguments, hugepages and N2/N3 bind address required by the selected deployment.

## Retina cluster definition

Declare matching `s72-ocudu` and `s72-ue` resources in `cluster_definition/<cluster>/retina_info.yml`. The gNB resource uses PCI addresses for its DPDK interfaces; the UESIM resource uses the Linux VLAN interfaces. MAC-address and VLAN arrays must have identical ordering on both sides.

```yaml
- name: <gnb-node>
  type: linux-x86
  backhaul:
    n2n3_bind_address: <gnb-backhaul-ip>
  resources:
    - type: ru
      model: s72-ocudu
      space: <tested-capacity>
      network_interface: [<gnb-fh-pci-1>, <gnb-fh-pci-2>]
      du_mac_addr: [<gnb-fh-mac-1>, <gnb-fh-mac-2>]
      ru_mac_addr: [<uesim-fh-mac-1>, <uesim-fh-mac-2>]
      vlan_tag_cp: ["<fh-vlan-1>", "<fh-vlan-2>"]
      vlan_tag_up: ["<fh-vlan-1>", "<fh-vlan-2>"]
      prach_port_id: "[4, 5, 6, 7]"
      dl_port_id: "[0, 1, 2, 3]"
      ul_port_id: "[0, 1, 2, 3]"

- name: <uesim-node>
  type: linux-x86
  backhaul:
    n2n3_bind_address: <uesim-backhaul-ip>
  resources:
    - type: ru
      model: s72-ue
      space: <tested-capacity>
      network_interface:
        - <uesim-fh-iface-1>.<fh-vlan-1>
        - <uesim-fh-iface-2>.<fh-vlan-2>
      du_mac_addr: [<gnb-fh-mac-1>, <gnb-fh-mac-2>]
      ru_mac_addr: [<uesim-fh-mac-1>, <uesim-fh-mac-2>]
      vlan_tag_cp: ["<fh-vlan-1>", "<fh-vlan-2>"]
      vlan_tag_up: ["<fh-vlan-1>", "<fh-vlan-2>"]
      prach_port_id: "[4, 5, 6, 7]"
      dl_port_id: "[0, 1, 2, 3]"
      ul_port_id: "[0, 1, 2, 3]"
```

`space` is the capacity reserved by Retina, not the number of NIC ports. Set it to the capacity that has been validated for the complete gNB and UESIM pair.

## Deployment and validation

1. Record the gNB PCI addresses, UESIM interface names and MAC addresses with `lspci -D`, `ip link` and `ethtool -i`.
2. Configure the switch VLANs and verify GPS lock and PTP grandmaster state.
3. Add the node resources to `retina_info.yml` and the `linuxptp` and TuneD services to `services.yaml`.
4. Apply the infrastructure configuration and let required host reboots complete.
5. Check the UESIM VLAN interfaces, the running `linuxptp` pod and PTP synchronisation.
6. Confirm the S72 resources are visible to Retina, then run a small S72 E2E test before increasing the UE or MIMO profile.

Useful checks:

```bash
ip link show <uesim-fh-iface-1>.<fh-vlan-1>
ip link show <uesim-fh-iface-2>.<fh-vlan-2>
kubectl get pods -A -o wide | grep -i linuxptp
ethtool -c <uesim-fh-iface-1>
ethtool -g <uesim-fh-iface-1>
```

If the test cannot reserve resources, check the matching `s72-ocudu` and `s72-ue` models, the advertised capacity, node labels/taints and Amarisoft licences. If uplink messages are late or missing, check PTP synchronisation, CPU isolation, host load, IRQ placement, NIC coalescing and ring counters before changing the radio configuration.
